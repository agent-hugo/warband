# Warband

Игры для нескольких телефонов: каждый игрок водит своего человечка по общей карте экранным джойстиком.
Заодно проверка связки **MQTT + WebRTC** для живой игры. Каждая игра лежит в своей папке, главная страница
ссылается на них.

- `fogtag/` — **догонялки в тумане**: [agent-hugo.github.io/warband/fogtag](https://agent-hugo.github.io/warband/fogtag/)

Старые ссылки-приглашения на главную (`#i=…`, `#host=…`) сами переходят в `fogtag/`. Если после выхода
новой версии страница не может загрузить свой код, она один раз перезагружается в обход кэша.

(Прежняя пошаговая карточная версия — тег `cards-v1`.)

## Догонялки в тумане: правила

- Один водит и бегает на четверть быстрее остальных. Кого он коснулся — тот теперь водит и пять секунд стоит,
  чтобы прежний водящий успел отбежать.
- Кто прячется и простоял на месте 15 секунд, у того мигает экран: через 5 секунд водящий увидит его на миникарте.
  Сдвинулся с места за эти 5 секунд — предупреждение снимается. Не успел — водящий видит его на миникарте,
  пока тот не набегает 5 секунд.
- Кнопка ⛶ рядом с меню разворачивает игру на весь экран (на iPhone браузер этого не умеет).
- Видно только то, что рядом и не за стеной. Кто сидит в кустах, того видно только вплотную.
- Раунд: 5 секунд водящий стоит, остальные прячутся, потом 2 минуты погони. Побеждает тот, кто водил меньше всех.
  Между раундами туман пропадает и видно всех. Игра начинается, когда в комнате двое и у каждого есть прямое
  соединение WebRTC с хостом (или он сам выбрал «только брокер»), чтобы никто не играл первые секунды через брокер.

## Как устроено

- **Хост** считает мир и правила 30 раз в секунду и рассылает снимки. Каждый игрок получает только тех,
  кого видит, поэтому подсмотреть сквозь туман нельзя. Хост — либо телефон одного из игроков
  (выбирается сам, если хоста нет), либо хост-страница на ноутбуке (`#host=КОД`), которая перехватывает комнату.
  Побеждает самый новый хост; телефон-хост, погасив экран, отдаёт комнату.
- **MQTT-брокер** (`warband/r/<КОД>/…`): кто хост (`host`, retained + last will), кто в комнате (`p/<id>`),
  обмен WebRTC-описаниями (`sig/<кому>/<от кого>`), позиции для следующего хоста (`pos`), и запасной канал
  игры (`up/<id>`, `dn/<id>`) — 10 сообщений в секунду, пока у игрока нет прямого соединения.
- **WebRTC DataChannel** без гарантии доставки и порядка: ввод от игрока и снимки от хоста идут напрямую,
  30 раз в секунду. STUN — публичный Google; TURN можно указать на главной в «Дополнительно».
- **Предсказание**: свой человечек двигается сразу (со своей скоростью: у водящего она выше, замерший стоит), а когда приходит позиция от хоста, ещё не учтённый
  хостом ввод проигрывается поверх неё. Чужие рисуются чуть в прошлом, между двумя снимками.
  В меню игрока это можно выключить, чтобы почувствовать задержку, и переключиться на «только брокер».
- **Диагностика WebRTC**: каждая попытка соединения записывает адреса обеих сторон, смену состояний ICE
  и пары адресов, которые браузер пробовал. Отчёт виден в меню игрока и на хост-странице, а последний
  отчёт каждого игрока и хоста лежит на брокере (`diag/<id>`, `diag/h-<id>`, retained на неделю).
- **Свой адрес в сети**: браузеры прячут адрес устройства за случайным именем `….local`, и не во всякой
  сети другое устройство может его разобрать (так не соединяются два Firefox). Галка «Показывать свой
  адрес в сети» в меню и на хост-странице открывает микрофон на время сбора адресов — тогда браузер
  показывает настоящий адрес. Звук никуда не идёт.

```sh
npm install
npm run dev          # http://<адрес>:5173/fogtag/
npm test
MQTT_TOKEN=... npm run net-smoke   # хост и два игрока через брокер
MQTT_TOKEN=... npm run diag -- КОД  # отчёты WebRTC комнаты с брокера
```

Токен брокера вводится на главной или приходит в ссылке-приглашении (`#i=…`, base64url: не шифрование)
и хранится только в браузере.
